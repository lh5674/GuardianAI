# GuardianAI 老年跌倒检测系统技术架构书

版本：0.1（Demo 设计稿）  
日期：2026 年 10 月 9 日  
适用对象：产品、算法、边缘端、后端、测试与养老服务团队

## 1 项目目标与边界

GuardianAI Demo 面向经授权的室内养老场景，使用固定摄像头和边缘 AI 识别疑似跌倒，并将事件发送给指定照护人员复核。首期目标是验证从视频采集、姿态估计、时序判别到告警闭环的可行性。系统仅提供辅助提醒，不作医疗诊断，也不能替代人工巡视或紧急呼叫系统。世界卫生组织指出，老年人是跌倒相关致命伤害的高风险人群之一，因而系统设计需同时重视漏报、误报与处置时延。[1]

Demo 范围：一个试点房间、两路固定视角、单台边缘推理设备、事件服务和照护端通知。多房间规模化、医疗级风险预测及自动拨打急救电话不在首期验收范围内。任何涉及真人采集的试点，须先获得明确同意并完成场地与数据保护审批。

## 2 总体架构

处理链路：摄像头采集 → 边缘视频解码 → 人体检测与 YOLO-Pose 关键点提取 → 跨帧跟踪 → 姿态特征与质量评估 → GRU 或 TCN 时序分类 → 规则融合与多帧确认 → 事件生成 → 本地队列 → 加密传输 → 告警服务 → 照护人员确认与记录。

边缘端承担视频解码、关键点提取和初步判断；默认不向云端传输连续原始视频。后端仅接收事件元数据、设备健康状态，以及经授权配置的短时证据片段。断网时边缘端缓存事件并在恢复后补传，持续保留本地声光提示或备用通知通道的配置能力。

### 2.1 主要模块与接口

- 视频采集：接入两路 1080p、25 fps、支持 RTSP/ONVIF 的 PoE 摄像头；统一时间戳并记录丢帧率。
- 姿态服务：YOLO-Pose 输出人体框、关键点坐标和置信度；先以小模型建立基线，再按真实场景精度与延迟选择模型。官方文档说明 Pose 输出关键点及其置信度，并支持导出到 TensorRT。[2]
- 跟踪与特征：按 track_id 聚合连续骨架，计算躯干角度、重心相对位移、身体长宽比、关键点速度及可见性；缺失关键点保留掩码，不用零值冒充观测。
- 时序判别：以 2–4 秒滑动窗口输入 GRU 与 TCN 候选模型，比较事件召回、误报与端侧延迟；模型输出疑似跌倒概率。
- 事件规则：结合模型分数、人体由站立向低位转移、落地后持续静止等证据，多帧确认并设置冷却时间，避免同一次事件重复报警。
- 告警服务：接收 event_id、device_id、camera_id、时间、风险等级、模型版本和可选证据引用；通过已授权渠道推送并记录“待确认、已确认、误报、已处理”状态。

### 2.2 事件接口草案

事件 API 使用 HTTPS 和设备身份认证。最小字段：event_id、occurred_at、device_id、camera_id、track_id（边缘端临时标识）、event_type、score、model_version、evidence_uri（可空）、delivery_status。event_id 用于幂等处理；不传姓名、房间住户身份或完整骨架序列作为默认字段。照护端确认结果与处理时间写入审计日志。

## 3 核心算法设计

### 3.1 数据与标注

采集站立、行走、坐下、弯腰、躺床、捡物、遮挡、多人交叉及模拟跌倒等场景。采用“事件级起止时间 + 人体轨迹 + 遮挡标签”的标注规则。训练、验证与测试按参与者及场地分组，避免同一人或同一录像相邻片段跨集合泄漏。真实跌倒样本不足时，模拟跌倒仅用于早期模型开发，验收需另列真实或经专家认可的外部数据结果。

### 3.2 关键点到时序模型

对关键点做人体框归一化，保留坐标、置信度、可见性掩码与时间间隔。GRU 基线适合有序序列；TCN 候选便于并行推理。两者使用相同数据切分与评价口径。阈值在验证集确定，测试集只做一次冻结评估。低置信度、画面外或持续遮挡时输出“无法可靠判断”，并可触发视角切换或设备异常提示。

### 3.3 多视角融合

两路视角分别推理并通过时间窗、空间区域与轨迹一致性关联事件。视角质量权重来自关键点可见率、人体框完整度和遮挡程度；若一侧被遮挡，优先使用另一侧的可靠证据。视角冲突时不简单求平均，保留不确定性并要求更长确认窗口或人工复核。

## 4 三项创新及分阶段验证

### 4.1 视觉步态风险评估

在明确同意且采集质量达标时，提取步速、步幅相对量、左右节律、摆动稳定性等跨日趋势。只生成“变化提示”，不输出临床诊断或未经验证的跌倒风险百分比。验证重点是同一人重复测量稳定性、场景变化鲁棒性及与专业评估的一致性；首期 Demo 可展示趋势原型。

### 4.2 多视角遮挡检测

联合估计视角可见性与遮挡来源，记录“可判别覆盖率”。当单视角遮挡、逆光或家具遮挡时，系统在另一视角寻求证据；双视角均不足时报告监测盲区。验收比较单视角与双视角在遮挡子集上的事件召回和误报变化。

### 4.3 个性化行为模型

在获得个人授权且积累足量正常活动样本后，建立每人活动基线，用于调整非典型动作的提示阈值。初期只做本地个性化校准，不以个人模型替代全局跌倒检测器。提供停用、重置与回退机制；按人群分层检查是否因个性化造成漏报增加。

## 5 边缘部署与可靠性

Demo 建议使用 NVIDIA Jetson Orin Nano Super 开发套件，配两路 PoE 摄像头、PoE 交换机、SSD、供电保护与本地网络设备。NVIDIA 官方资料给出的开发套件参考价为 249 美元，最高 67 INT8 TOPS；实际采购价、供应和兼容性需询价核对。[3] 推理链路优先采用 JetPack + TensorRT，并对 FP16 与 INT8 量化后的精度差异做回归测试。TensorRT 是 NVIDIA 的推理优化 SDK。[4]

设备启动后进行摄像头、存储、网络和模型版本自检。录像流异常、磁盘不足、设备过热或推理服务退出时发出“监测不可用”告警。事件本地队列采用持久化和重试；所有通知有送达记录、超时升级和人工关闭路径。目标是避免无网络时静默丢失事件。

## 6 隐私与安全

采用最小采集原则：默认只保留边缘端短时环形缓存与事件元数据；证据片段仅在经授权的试点中启用。摄像头避开浴室、更衣区等高私密区域，并设置画面遮罩。访问采用角色权限、最小授权和多因素认证；传输使用 TLS，静态存储加密；密钥不写入代码仓库。对查看、导出、删除和共享操作保留审计日志。

试点开始前形成告知与同意记录，明确目的、访问人员、保留期、撤回方式和事件处置流程。保留期由实际适用法律、合作机构政策及试点协议确定，不在方案阶段虚构统一天数。支持按人或事件删除，并建立数据泄露响应流程。原始视频、个人资料和密钥不得提交到 GitHub。

## 7 测试与验收

验收分为离线算法、端侧性能、告警链路、隐私安全及现场试点五层。以下为 Demo 讨论目标，需在场地、样本规模和人工处置能力确定后由项目方正式冻结；不能当作已实现性能承诺。

- 算法：在独立测试集报告事件级召回率、精确率、误报次数/摄像头·日，并给出遮挡、光照、多人和辅助器具等分组结果。建议讨论目标：事件召回率不低于 90%，误报不高于 0.5 次/摄像头·日；任何真实跌倒漏报须逐例复盘。
- 时延：从跌倒事件发生到边缘端形成告警的 P95 不高于 5 秒；通知送达链路另测 P95。
- 可靠性：断网后事件进入本地队列，网络恢复后补传且不重复；摄像头断流和存储不足能被发现。
- 安全：验证访问控制、审计、传输加密、删除与撤回流程；对误授权和泄露场景做演练。
- 现场：连续试点至少 2 周，记录有效监测时长、盲区、告警处理时间和一线照护人员反馈。没有足够真实事件时，不能仅凭模拟动作宣称临床有效。

## 8 开发阶段与交付物

- 第 1–2 周：场地勘查、隐私评审、设备采购与摄像头安装；交付安装图、数据管理方案、标注规范。
- 第 3–4 周：视频采集、YOLO-Pose 基线、跟踪和样本标注；交付可复现数据切分与离线基线报告。
- 第 5–6 周：GRU/TCN 训练、规则融合、边缘部署与事件 API；交付端侧服务、接口定义和性能报告。
- 第 7 周：多视角遮挡与告警闭环；交付照护端流程和故障演练记录。
- 第 8 周：现场试点、验收与复盘；交付测试报告、风险清单及下一阶段决策建议。步态与个性化功能以研究原型评估，不阻塞基础跌倒检测 Demo 验收。

## 9 待决事项

需由团队确认试点地区与适用法规、摄像头安装位置、事件通知渠道、数据保留期、预算币种、采购供应商、负责人和最终验收阈值。上述待决事项在任务看板中跟踪。
